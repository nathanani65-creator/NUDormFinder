# NU Dorm Finder

ระบบค้นหาที่พักรอบมหาวิทยาลัยนเรศวร (หอพัก อพาร์ตเมนต์ คอนโด บ้านเช่า) โดยเชื่อม
**ประตู → โซน/ซอย → ที่พัก** เข้ากับแผนที่และตัวกรอง

เทคนิคหลัก: **Faceted Search** (การค้นหาแบบใช้ตัวกรองตามเงื่อนไข พร้อมตัวเลขจำนวนผลลัพธ์ข้างตัวเลือกแต่ละตัว)
ร่วมกับ **การแสดงผลข้อมูลเชิงพื้นที่บนแผนที่** และ **ระบบบริหารจัดการข้อมูลที่พัก** (ส่งข้อมูล → ตรวจสอบ → เผยแพร่)

> ระบบนี้ยังไม่ใช่ Semantic Search เพราะไม่มีส่วนตีความประโยคภาษาธรรมชาติ ช่องค้นหาข้อความเป็นการจับคำ (keyword) กับชื่อ ที่อยู่ และชื่อซอยเท่านั้น

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป (ใช้ SQLite ที่มากับ Node ไม่ต้องติดตั้งฐานข้อมูลแยก)

```bash
npm install
npm start               # http://localhost:3000 (ฐานข้อมูลว่างจะสร้างประตู โซน ซอย และบัญชีผู้ดูแลให้ ไม่มีที่พัก)
npm run seed            # ล้างฐานข้อมูลแล้วสร้างข้อมูลตั้งต้นใหม่
npm run remove-samples  # ลบที่พักสมมติออกจากฐานข้อมูลเดิม (ที่พักที่นำเข้าจากชีตไม่ถูกลบ)
npm test                # ทดสอบกติกาการกรอง
```

จากนั้นเข้าสู่ระบบผู้ดูแลที่ `/login` แล้วนำเข้าที่พักจริงที่ `/admin` → แท็บ "นำเข้าจากชีต"
(ไฟล์ชีตและฐานข้อมูลไม่อยู่ใน git เพราะมีข้อมูลติดต่อของเจ้าของที่พัก แต่ละเครื่องจึงต้องนำเข้าเอง)

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| ผู้ดูแลระบบ | admin@nudorm.local | admin1234 (เปลี่ยนได้ด้วย env `ADMIN_EMAIL`, `ADMIN_PASSWORD` ตอนสร้างฐานข้อมูล) |

ต้องการที่พักสมมติ 14 รายการไว้ทดสอบ ให้ตั้ง `SEED_SAMPLES=true` ก่อนรัน `npm run seed`
(จะได้บัญชีผู้ประกอบการตัวอย่าง provider@nudorm.local / provider1234 ด้วย)

สมาชิกสมัครเองได้ที่ `/login` (เลือกประเภทบัญชี "สมาชิก" หรือ "ผู้ประกอบการ" บัญชีผู้ดูแลระบบสมัครผ่านหน้าเว็บไม่ได้)

## บทบาทผู้ใช้

| บทบาท | ทำได้ |
|---|---|
| ผู้ใช้ทั่วไป | ค้นหา กรอง ดูรายละเอียด เปรียบเทียบได้สูงสุด 3 แห่ง (เก็บในแท็บเบราว์เซอร์ หายเมื่อปิดเว็บไซต์) |
| สมาชิก | ทุกอย่างของผู้ใช้ทั่วไป + บันทึกที่พักเป็นรายการโปรด และเก็บชุดเปรียบเทียบไว้ในบัญชี (หน้า `/saved`) |
| ผู้ประกอบการ | ส่งประกาศ/เสนอแก้ไขเฉพาะประกาศของตน ทุกอย่างรอผู้ดูแลอนุมัติก่อนเผยแพร่ (หน้า `/provider`) |
| ผู้ดูแลระบบ | อนุมัติ/ไม่อนุมัติ (ต้องระบุเหตุผล) ประกาศและคำขอแก้ไข จัดการประตู โซน ซอย (หน้า `/admin`) |

สิทธิ์ตรวจทั้งหน้าเว็บและ API (`test/roles.test.js`) ประกาศที่ยังไม่เผยแพร่ไม่ปรากฏในค้นหา หน้ารายละเอียด หรือการเปรียบเทียบสาธารณะ

รูปหน้าแรก: บันทึกภาพประกอบเป็น `public/img/hero.webp` (เปลี่ยนรูปได้โดยแทนที่ไฟล์นี้)

## ⚠ ก่อนใช้งานจริง

- ฐานข้อมูลที่เคยสร้างพร้อมที่พักสมมติ (ชื่อลงท้าย "(สมมติ)") ให้รัน `npm run remove-samples` (สำรองฐานข้อมูลให้ก่อนลบ ดูรายการก่อนได้ด้วย `-- --dry-run`)
- เปลี่ยนรหัสผ่านผู้ดูแลก่อนเปิดใช้งาน

## นำขึ้นเว็บจริง (Railway)

1. สร้างโปรเจกต์ใหม่ใน Railway → **Deploy from GitHub repo** → เลือก repo นี้ (ใช้ `npm start` และ Node 24 จาก `.nvmrc`)
2. เพิ่ม **Volume** ให้ service แล้วตั้ง Mount path เป็น `/data` (เก็บฐานข้อมูลและรูปที่อัปโหลดไม่ให้หายเมื่อ deploy ใหม่)
3. ตั้ง Variables

   | ตัวแปร | ค่า |
   |---|---|
   | `NODE_ENV` | `production` (ไม่ใส่ที่พักสมมติ และคุกกี้เข้าสู่ระบบใช้ได้เฉพาะ HTTPS) |
   | `DB_PATH` | `/data/nudorm.db` |
   | `UPLOAD_DIR` | `/data/uploads` |
   | `ADMIN_EMAIL` | อีเมลผู้ดูแล |
   | `ADMIN_PASSWORD` | รหัสผ่านผู้ดูแล (ใช้ตอนสร้างฐานข้อมูลครั้งแรกเท่านั้น) |

4. Settings → Networking → **Generate Domain** เพื่อได้ลิงก์เว็บ
5. เข้าสู่ระบบผู้ดูแลที่ `/admin` → แท็บ **นำเข้าจากชีต** → อัปโหลดไฟล์ .xlsx ที่ดาวน์โหลดจาก Google Sheets

ไฟล์ชีตและโฟลเดอร์รูปไม่ถูกเก็บใน Git (มีข้อมูลติดต่อเจ้าของหอ และ repo เป็นสาธารณะ) อัปเดตข้อมูลบนเว็บจริงด้วยการอัปโหลดชีตใหม่ในหน้าผู้ดูแล

## นำเข้าข้อมูลจากชีตฐานข้อมูล

ดาวน์โหลดชีต "NU Dorm Finder - ฐานข้อมูลที่พัก" เป็น .xlsx แล้วรัน

```bash
npm run import -- "ไฟล์.xlsx" --dry-run   # ตรวจอย่างเดียว ไม่บันทึก
npm run import -- "ไฟล์.xlsx"             # นำเข้ารายการใหม่และเผยแพร่ (สำรองฐานข้อมูลไว้ใน data/ ก่อนทุกครั้ง)
npm run import -- "ไฟล์.xlsx" --update    # อัปเดตรายการที่เคยนำเข้าด้วยข้อมูลล่าสุดจากชีต
```

- ข้อมูลจากชีตเป็นข้อมูลที่ทีมงานรวบรวมเอง จึง **เผยแพร่ทันที ไม่ต้องรอผู้ดูแลอนุมัติ**
  (ประกาศที่ผู้ประกอบการส่งเองบนเว็บยังต้องรอผู้ดูแลอนุมัติ และต้องมีข้อมูลจำเป็นครบก่อนอนุมัติ)
- จับคู่กับชีตด้วย `property_id` นำเข้าซ้ำไม่เกิดรายการซ้ำ ชีตเป็นต้นฉบับ: `--update` เขียนทับการแก้ไขบนเว็บของรายการที่มาจากชีต
  ยกเว้นรายการที่ผู้ดูแลซ่อนหรือไม่อนุมัติไว้
- ส่วนที่ชีตยังไม่มีข้อมูล หน้าเว็บแสดง "รอตรวจสอบ" ที่พักที่ยังไม่มีพิกัดแสดงในรายการผลค้นหา (เรียงไว้ท้าย)
  แต่ไม่มีหมุดบนแผนที่และไม่ผ่านตัวกรองระยะทาง
- นำเข้าผ่านหน้าเว็บได้ที่ `/admin` → แท็บ "นำเข้าจากชีต" (มีปุ่มตรวจก่อนโดยไม่บันทึก)
- ซอยในชีตที่ยังไม่มีบนเว็บ ระบบสร้างให้อัตโนมัติใต้ประตูที่ใกล้ที่สุดของหอนั้น
- ผู้ใช้ทั่วไปเห็นเฉพาะที่พักที่มี **ราคาห้องหรือรูปอย่างน้อยหนึ่งอย่าง** ที่เหลือยังอยู่ในหน้าผู้ดูแล และขึ้นเว็บเองเมื่อเติมข้อมูลแล้วนำเข้าใหม่
  (ตั้ง `SHOW_INCOMPLETE_LISTINGS=true` เพื่อแสดงทุกรายการ)
- ข้าม `สถานะการคัดเลือก = ไม่อยู่ในขอบเขต` / ห้องที่ยังไม่มีราคา / สถานที่ใกล้เคียงที่ไม่มีระยะหรือพิกัด

## กติกาการกรอง

| กลุ่มเงื่อนไข | ภายในกลุ่ม | ตัวอย่าง |
|---|---|---|
| ประเภทที่พัก | OR | หอพัก OR คอนโด |
| ประตู | OR (ที่พักเกี่ยวข้องกับประตูใดก็ได้ที่เลือก) | ประตู 4 OR ประตู 3 |
| โซน / ซอย | OR | |
| ราคา | มีห้องอย่างน้อย 1 ประเภทอยู่ในช่วงราคา | ≤ 3,000 |
| สิ่งอำนวยความสะดวก | **AND** (ต้องมีครบทุกข้อ) | แอร์ AND ที่จอดรถ |
| **ระหว่างกลุ่ม** | **AND** | ประตู 4 AND ≤ 3,000 AND มีแอร์ |

โค้ดอยู่ที่ [server/search.js](server/search.js) และทดสอบใน [test/search.test.js](test/search.test.js)
(รวมถึงตัวอย่างจากเอกสาร: ประตู 4 → ซอยกระบอกวิศวะ → ≤ 3,000 บาท → มีแอร์)

## ตัวเลขจำนวนผลลัพธ์ข้างตัวเลือก (Facet Counts)

API `/api/properties` คืน `facets` มาพร้อมผลลัพธ์ หน้าค้นหาแสดงเป็น `(n)` ข้างตัวเลือก และอัปเดตทุกครั้งที่เปลี่ยนตัวกรอง

| กลุ่ม | วิธีนับ | ความหมายของตัวเลข |
|---|---|---|
| ประเภท ประตู โซน ซอย (OR) | **Disjunctive** — ไม่ใส่เงื่อนไขของกลุ่มตัวเอง แต่ใส่กลุ่มอื่นครบ | จำนวนที่พักถ้าเลือกค่านี้ในกลุ่ม ร่วมกับตัวกรองกลุ่มอื่น (เลือกประตู 4 แล้ว ประตู 3 ยังมีตัวเลข) |
| สิ่งอำนวยความสะดวก (AND) | **Conjunctive** — ใส่เงื่อนไขทุกกลุ่มรวมข้อที่ติ๊กอยู่ | จำนวนที่พักที่จะเหลือถ้าติ๊กข้อนี้เพิ่ม |
| ราคา | นับตามช่วงสำเร็จรูป ≤2,500 / ≤3,000 / ≤4,000 / ≤5,000 / >5,000 โดยไม่ใส่ช่วงราคาเดิม | จำนวนที่พักถ้ากดปุ่มช่วงนั้น |

- นับเป็นจำนวน **ที่พัก** (ไม่ใช่จำนวนห้อง) และนับเฉพาะที่พักที่เผยแพร่แล้ว
- ตัวเลือกที่ได้ 0 แสดงสีจางและกดไม่ได้ ยกเว้นตัวที่ติ๊กอยู่ เพื่อให้เอาติ๊กออกได้
- การทดสอบตรวจว่าตัวเลขทุกตัวเท่ากับจำนวนผลลัพธ์จริงเมื่อเลือกตัวเลือกนั้น ในหลายชุดตัวกรอง (`test/search.test.js`)

## ข้อมูลเชิงพื้นที่

- เก็บ **ประตู / โซน / ซอย / พิกัด** แยกกัน: ซอยเชื่อมได้หลายประตู (`soi_gates`) โซนมีประตูหลัก (`zone_gates`)
- ที่พักเก็บ **รายการเดียว** แล้วบันทึกประตูที่เกี่ยวข้องใน `property_gates` (ที่พักในซอยที่เชื่อมสองประตูไม่ต้องสร้างซ้ำ)
- ระยะทางคำนวณด้วยสูตร Haversine และแสดงเป็น **"ระยะเส้นตรง"** ทุกจุด ไม่ใช่ระยะเดินหรือขับรถ
- แผนที่ใช้ Leaflet + OpenStreetMap

## การจัดการและตรวจสอบข้อมูล

1. ผู้ประกอบการสมัครสมาชิก → ส่งประกาศ (สถานะ `pending`)
2. ผู้ดูแลเห็นรายการตรวจ (ข้อมูลจำเป็นครบไหม) และ **รายการที่อาจซ้ำ** (ชื่อเหมือนกัน หรืออยู่ในรัศมี 40 ม.) → อนุมัติ / ไม่อนุมัติพร้อมเหตุผล
3. แก้ไขประกาศที่เผยแพร่แล้ว → เกิด **คำขอแก้ไข** ข้อมูลเดิมยังแสดงจนกว่าผู้ดูแลจะอนุมัติ (มีหน้าเทียบก่อน/หลัง)
4. ผู้ใช้ทั่วไปกด "แจ้งข้อมูลไม่ถูกต้อง" → เข้าคิวผู้ดูแล
5. ทุกที่พักแสดง **แหล่งข้อมูล** และ **วันที่ตรวจสอบล่าสุด** (สีเขียว ≤ 90 วัน, เหลือง ≤ 180 วัน, แดงเกินกว่านั้น)

## ข้อมูลสำหรับประเมินผลวิจัย

ระบบบันทึกเหตุการณ์แบบไม่ระบุตัวตน (`gate_select`, `search`, `view_property`, `contact_click`) พร้อมเวลา
ดาวน์โหลดเป็น CSV ได้ที่หน้าผู้ดูแล → "ข้อมูลการใช้งาน" ใช้วัดว่าผู้ทดลองทำภารกิจ
เช่น "หาที่พักใกล้ประตู 4 ราคาไม่เกิน 3,000 บาทและมีที่จอดรถ" สำเร็จหรือไม่และใช้เวลาเท่าไร

## โครงสร้างโปรเจกต์

```
server/
  index.js        API และเสิร์ฟหน้าเว็บ (Express)
  db.js           โครงสร้างฐานข้อมูล SQLite
  search.js       การค้นหาแบบใช้ตัวกรอง + ระยะเส้นตรง
  properties.js   ตรวจความถูกต้อง บันทึก และรายการตรวจของผู้ดูแล
  auth.js         รหัสผ่าน (scrypt) และ session
  seed.js         ข้อมูลเริ่มต้น/ตัวอย่าง
public/
  index.html      หน้าแรก: แผนที่ประตู ที่พักแนะนำ โซน
  search.html     หน้าผลการค้นหา: ตัวกรอง รายการ แผนที่
  property.html   หน้ารายละเอียดที่พัก
  provider.html   หน้าผู้ประกอบการ
  admin.html      หน้าผู้ดูแลระบบ (js/admin.js)
test/             การทดสอบ (node:test)
```
