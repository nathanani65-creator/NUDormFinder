# NU Dorm Finder

ระบบค้นหาที่พักรอบมหาวิทยาลัยนเรศวร (หอพัก อพาร์ตเมนต์ คอนโด บ้านเช่า) โดยเชื่อม
**ประตู → โซน/ซอย → ที่พัก** เข้ากับแผนที่และตัวกรอง

เทคนิคหลัก: **การค้นหาแบบใช้ตัวกรองตามเงื่อนไข (Filter-based / Faceted Search)**
ร่วมกับ **การแสดงผลข้อมูลเชิงพื้นที่บนแผนที่** และ **ระบบบริหารจัดการข้อมูลที่พัก** (ส่งข้อมูล → ตรวจสอบ → เผยแพร่)

> ระบบนี้ยังไม่ใช่ Semantic Search เพราะไม่มีส่วนตีความประโยคภาษาธรรมชาติ ช่องค้นหาข้อความเป็นการจับคำ (keyword) กับชื่อ ที่อยู่ และชื่อซอยเท่านั้น

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป (ใช้ SQLite ที่มากับ Node ไม่ต้องติดตั้งฐานข้อมูลแยก)

```bash
npm install
npm start          # http://localhost:3000 (ฐานข้อมูลว่างจะใส่ข้อมูลตัวอย่างให้อัตโนมัติ)
npm run seed       # ล้างฐานข้อมูลแล้วใส่ข้อมูลตัวอย่างใหม่
npm test           # ทดสอบกติกาการกรอง
```

บัญชีตัวอย่าง (เปลี่ยนรหัสผู้ดูแลได้ด้วย env `ADMIN_EMAIL`, `ADMIN_PASSWORD` ตอนรัน seed):

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| ผู้ดูแลระบบ | admin@nudorm.local | admin1234 |
| ผู้ประกอบการ | provider@nudorm.local | provider1234 |

รูปหน้าแรก: บันทึกภาพประกอบเป็น `public/img/hero.webp` (เปลี่ยนรูปได้โดยแทนที่ไฟล์นี้)

## ⚠ ก่อนใช้งานจริง

- **พิกัดประตูเป็นค่าประมาณ** ต้องตรวจกับตำแหน่งจริง แล้วแก้ในหน้าผู้ดูแล → แท็บ "ประตู" (ลากหมุดบนแผนที่ได้)
- **ที่พักตัวอย่างทั้ง 14 รายการเป็นข้อมูลสมมติ** (ชื่อลงท้าย "(สมมติ)") และซอยที่มีคำว่า "(ตัวอย่าง)" ก็เป็นซอยสมมติ มีเพียง "ซอยกระบอกวิศวะ" ที่มาจากเอกสารแนวคิด
- ลบข้อมูลตัวอย่างและเปลี่ยนรหัสผ่านผู้ดูแลก่อนเปิดใช้งาน

## กติกาการกรอง

| กลุ่มเงื่อนไข | ภายในกลุ่ม | ตัวอย่าง |
|---|---|---|
| ประเภทที่พัก | OR | หอพัก OR คอนโด |
| ประตู | OR (ที่พักเกี่ยวข้องกับประตูใดก็ได้ที่เลือก) | ประตู 4 OR ประตู 3 |
| โซน / ซอย | OR | |
| ราคา | มีห้องอย่างน้อย 1 ประเภทอยู่ในช่วงราคา | ≤ 3,000 |
| สิ่งอำนวยความสะดวก | **AND** (ต้องมีครบทุกข้อ) | แอร์ AND ที่จอดรถ |
| **ระหว่างกลุ่ม** | **AND** | ประตู 4 AND ≤ 3,000 AND มีแอร์ |

โค้ดอยู่ที่ [server/search.js](server/search.js) และทดสอบใน [test/search.test.js](test/search.test.js)
(รวมถึงตัวอย่างจากเอกสาร: ประตู 4 → ซอยกระบอกวิศวะ → ≤ 3,000 บาท → มีแอร์)

## ข้อมูลเชิงพื้นที่

- เก็บ **ประตู / โซน / ซอย / พิกัด** แยกกัน: ซอยเชื่อมได้หลายประตู (`soi_gates`) โซนมีประตูหลัก (`zone_gates`)
- ที่พักเก็บ **รายการเดียว** แล้วบันทึกประตูที่เกี่ยวข้องใน `property_gates` (ที่พักในซอยที่เชื่อมสองประตูไม่ต้องสร้างซ้ำ)
- ระยะทางคำนวณด้วยสูตร Haversine และแสดงเป็น **"ระยะเส้นตรง"** ทุกจุด ไม่ใช่ระยะเดินหรือขับรถ
- แผนที่ใช้ Leaflet + OpenStreetMap

## การจัดการและตรวจสอบข้อมูล

1. ผู้ประกอบการสมัครสมาชิก → ส่งประกาศ (สถานะ `pending`)
2. ผู้ดูแลเห็นรายการตรวจ (ข้อมูลจำเป็นครบไหม) และ **รายการที่อาจซ้ำ** (ชื่อเหมือนกัน หรืออยู่ในรัศมี 40 ม.) → อนุมัติ / ไม่อนุมัติพร้อมเหตุผล
3. แก้ไขประกาศที่เผยแพร่แล้ว → เกิด **คำขอแก้ไข** ข้อมูลเดิมยังแสดงจนกว่าผู้ดูแลจะอนุมัติ (มีหน้าเทียบก่อน/หลัง)
4. ผู้ใช้ทั่วไปกด "แจ้งข้อมูลไม่ถูกต้อง" → เข้าคิวผู้ดูแล
5. ทุกที่พักแสดง **แหล่งข้อมูล** และ **วันที่ตรวจสอบล่าสุด** (สีเขียว ≤ 90 วัน, เหลือง ≤ 180 วัน, แดงเกินกว่านั้น)

## ข้อมูลสำหรับประเมินผลวิจัย

ระบบบันทึกเหตุการณ์แบบไม่ระบุตัวตน (`gate_select`, `search`, `view_property`, `contact_click`) พร้อมเวลา
ดาวน์โหลดเป็น CSV ได้ที่หน้าผู้ดูแล → "ข้อมูลการใช้งาน" ใช้วัดว่าผู้ทดลองทำภารกิจ
เช่น "หาที่พักใกล้ประตู 4 ราคาไม่เกิน 3,000 บาทและมีที่จอดรถ" สำเร็จหรือไม่และใช้เวลาเท่าไร

## โครงสร้างโปรเจกต์

```
server/
  index.js        API และเสิร์ฟหน้าเว็บ (Express)
  db.js           โครงสร้างฐานข้อมูล SQLite
  search.js       การค้นหาแบบใช้ตัวกรอง + ระยะเส้นตรง
  properties.js   ตรวจความถูกต้อง บันทึก และรายการตรวจของผู้ดูแล
  auth.js         รหัสผ่าน (scrypt) และ session
  seed.js         ข้อมูลเริ่มต้น/ตัวอย่าง
public/
  index.html      หน้าแรก: แผนที่ประตู ที่พักแนะนำ โซน
  search.html     หน้าผลการค้นหา: ตัวกรอง รายการ แผนที่
  property.html   หน้ารายละเอียดที่พัก
  provider.html   หน้าผู้ประกอบการ
  admin.html      หน้าผู้ดูแลระบบ (js/admin.js)
test/             การทดสอบ (node:test)
```
